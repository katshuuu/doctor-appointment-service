# Текст защиты ПР10

Сущности методички Roomly в этом проекте: **Room → врач**, **User → пациент**, **Booking → запись**.

Админка: http://127.0.0.1:8000/admin/

---

## 1. Настройка административной панели

Настройка административной панели демонстрируется классами `DoctorAdmin`, `PatientAdmin` и `AppointmentAdmin`: у каждой модели заданы столбцы списка, ссылки на карточку, поиск, фильтры и сортировка.

файлы: [apps/doctors/admin.py](apps/doctors/admin.py), [apps/patients/admin.py](apps/patients/admin.py), [apps/appointments/admin.py](apps/appointments/admin.py)

В браузере откройте `/admin/` и разделы «Врачи», «Пациенты», «Записи на прием».

- `list_display` — колонки списка;
- `list_display_links` — поля-ссылки на карточку;
- `search_fields` — поиск, в том числе по связанным именам (`doctor__name`, `patient__name`);
- `list_filter` — боковые фильтры, у записей есть фильтр по `status`;
- `ordering` — сортировка по умолчанию.

Найдите запись по «Смирнова» и включите фильтр статуса «Отменено».

## 2. Связанные объекты в административной панели

Связанные записи показываются таблицей `TabularInline`: на карточке врача — `DoctorAppointmentInline`, на карточке пациента — `PatientAppointmentInline`.

файлы: [apps/appointments/admin.py](apps/appointments/admin.py), [apps/doctors/admin.py](apps/doctors/admin.py), [apps/patients/admin.py](apps/patients/admin.py), [apps/appointments/models.py](apps/appointments/models.py)

Откройте врача «Смирнова Анна Сергеевна»: внизу таблица её записей. `extra = 0` — без пустых форм, `can_delete = False` — историю из inline не удалить.

Связь задаёт `ForeignKey` с `related_name="appointments"` и `on_delete=models.PROTECT`: врача или пациента нельзя удалить, пока на них есть записи.

## 3. Изменение модели и применение миграций

Изменение модели и применение миграций демонстрируются цепочкой файлов ПР10: `makemigrations` создаёт операцию, `migrate` меняет базу.

файлы: [apps/appointments/migrations/0002_appointment_status.py](apps/appointments/migrations/0002_appointment_status.py), [apps/doctors/migrations/0002_doctor_slug.py](apps/doctors/migrations/0002_doctor_slug.py), [apps/doctors/migrations/0005_doctor_name_max_length.py](apps/doctors/migrations/0005_doctor_name_max_length.py), [apps/patients/migrations/0003_patient_name_max_length.py](apps/patients/migrations/0003_patient_name_max_length.py)

Пример учебного изменения поля: `max_length` имени врача и пациента увеличен с 200 до 250. Покажите `AlterField` в миграции.

```text
python manage.py makemigrations --check
python manage.py showmigrations
python manage.py migrate
```

`makemigrations` только описывает разницу моделей. `migrate` выполняет SQL. Пока миграция не применена, поле в базе не изменится.

## 4. Преобразование существующих данных при смене модели записи

Преобразование данных выполняется миграцией [apps/appointments/migrations/0003_migrate_appointment_statuses.py](apps/appointments/migrations/0003_migrate_appointment_statuses.py): `is_cancelled=True` → `status="cancelled"`, иначе → `"active"`.

Порядок: [0002](apps/appointments/migrations/0002_appointment_status.py) добавляет `status` → 0003 переносит значения → [0004](apps/appointments/migrations/0004_remove_appointment_is_cancelled.py) удаляет старое поле.

Используется `apps.get_model`, потому что историческая модель ещё содержит `is_cancelled`. Записи 3, 7 и 12 стали `CANCELLED`. Завершённых в исходных данных не было, `COMPLETED` автоматически не проставлялся.

## 5. Работа с моделями через Django Shell

Работу с моделями через Shell можно показать на чтении объекта, изменении атрибута в памяти и повторном чтении из базы.

файл: [apps/appointments/models.py](apps/appointments/models.py)

```text
python manage.py shell
```

```python
from apps.appointments.models import Appointment
a = Appointment.objects.select_related("doctor", "patient").get(pk=1)
print(a.status)
a.status = Appointment.Status.COMPLETED
print("в памяти:", a.status)
print("в базе:", Appointment.objects.get(pk=1).status)
```

Пока нет `save()`, база не меняется. Объект в памяти — копия строки.

## 6. Создание, изменение и удаление средствами ORM

CRUD демонстрируется на отдельной тестовой записи, не на 15 исходных строках.

файлы: [apps/appointments/models.py](apps/appointments/models.py), [tests/test_orm.py](tests/test_orm.py)

Создайте специальность, врача, пациента и запись, вызовите `cancel()`, затем удалите запись и связанные объекты. Удаление врача до удаления записи вызывает `ProtectedError` из‑за `on_delete=PROTECT`. Метод `cancel()` меняет только статус и не удаляет строку.

## 7. QuerySet и фильтрация по нескольким условиям

Фильтрацию по нескольким условиям можно показать в `appointments()`: дата, врач, пациент, статус и поиск накладываются на один QuerySet.

файл: [apps/appointments/views.py](apps/appointments/views.py)

Браузер: `/appointments/?date=2026-09-15&doctor=1&status=active`.

Сначала `for_date()`, затем `filter(doctor_id=...)`, затем `rows.active()`. Каждый вызов сужает набор. Если убрать врача, выборка расширится.

---

## 8. Фильтрация по полям связанных моделей

Фильтрация по связанным моделям выполняется через `doctor__name` и `patient__name`.

файл: [apps/appointments/views.py](apps/appointments/views.py)

Поиск `q=Сидоров` даёт `Q(patient__name__icontains=...) | Q(doctor__name__icontains=...)`. ORM делает JOIN. Это не фильтр только по `doctor_id`. Сортировка `"doctor": ("doctor__name", ...)` тоже идёт по связанному полю.

---

## 9. Собственный менеджер и методы QuerySet

Собственный менеджер — `AppointmentQuerySet` и `objects = AppointmentManager()`.

файл: [apps/appointments/models.py](apps/appointments/models.py)

Методы: `active()`, `cancelled()`, `completed()`, `for_date()`.

```python
Appointment.objects.count()              # 15
Appointment.objects.active().count()     # 12
Appointment.objects.cancelled().count()  # 3
Appointment.objects.completed().count()  # 0
```

Те же методы используются в [apps/appointments/views.py](apps/appointments/views.py) и [apps/doctors/views.py](apps/doctors/views.py), поэтому условие статуса не копируется.

## 10. Обработка пользовательского ввода

Ввод из `request.GET` проверяется до запроса: дата через `_parse_date()`, идентификаторы только если `.isdigit()`, неизвестный `sort` сбрасывается на `date`.

файлы: [apps/appointments/views.py](apps/appointments/views.py), [apps/doctors/views.py](apps/doctors/views.py)

`/appointments/?date=не-дата` показывает «Укажите корректную дату.» без исключения. `page=abc` обрабатывает `Paginator.get_page()`.

---

## 11. Динамическая сортировка

Динамическая сортировка идёт через белый список `SORT_FIELDS`, а не через сырую строку из URL.

файл: [apps/appointments/views.py](apps/appointments/views.py)

Допустимы `date`, `doctor`, `patient`. `/appointments/?sort=doctor` меняет порядок. `/appointments/?sort=hack` снова сортирует по дате.

---

## 12. Выбор полей через values()

Выбор только нужных полей через `values()` показывается в статистике, а не в списке записей.

файл: [apps/appointments/views.py](apps/appointments/views.py) — функция `statistics`

`Doctor.objects.annotate(...).values("doctor_name", "appointments_count")` возвращает словари. Список записей оставляет объекты модели, потому что шаблон [appointment_list.html](apps/appointments/templates/appointments/appointment_list.html) читает `appointment.patient.name` и статус.

---

## 13. annotate() и F()

Дополнительные поля считаются так: `annotate(doctor_name=F("doctor__name"), patient_name=F("patient__name"))`.

файл: [apps/appointments/views.py](apps/appointments/views.py)

`F()` берёт значение из связанной таблицы на стороне SQL. В статистике то же: `doctor_name=F("name")` перед `values()`.

## 14. Получение объекта и обработка отсутствия

Отсутствие объекта обрабатывается через `DoesNotExist` и ответ 404, а не необработанным исключением.

файлы: [apps/doctors/views.py](apps/doctors/views.py), [apps/appointments/views.py](apps/appointments/views.py)

Это тот же смысл, что у `get_object_or_404`, но шаблон проекта показывает «Врач не найден» / «Запись не найдена».

- `/doctors/smirnova-anna-sergeevna-1/` — 200
- `/doctors/neizvestnyj-vrach-999/` — 404
- `/appointments/999/` — 404

## 15. slug и get_absolute_url()

URL карточки врача формируется методом `get_absolute_url()` по уникальному `slug`.

файлы: [apps/doctors/models.py](apps/doctors/models.py), [apps/doctors/urls.py](apps/doctors/urls.py), [apps/doctors/templates/doctors/includes/doctor_card.html](apps/doctors/templates/doctors/includes/doctor_card.html), [apps/doctors/admin.py](apps/doctors/admin.py)

Маршрут `"<slug:slug>/"`, имя `doctors:detail`. `reverse("doctors:detail", kwargs={"slug": self.slug})` даёт `/doctors/smirnova-anna-sergeevna-1/`. В шаблоне `{{ doctor.get_absolute_url }}`. В админке — «Посмотреть на сайте» и столбец `site_link`. Маршрут `available/` объявлен раньше `slug`, чтобы не перехватить слово `available`.

Вычисляемое поле проекта — `Patient.is_minor` (`GeneratedField`, `db_persist=True`): `age < 18`.

## 17. Агрегированная статистика

Агрегированная статистика строится `aggregate(Count, filter=Q(status=...))`.

файлы: [apps/appointments/views.py](apps/appointments/views.py), [apps/appointments/templates/appointments/statistics.html](apps/appointments/templates/appointments/statistics.html)

Страница `/appointments/statistics/`: всего 15, активных 12, отменённых 3, завершённых 0. `total_bookings` считает все строки, остальные счётчики — только выбранный статус.

---

## 18. Групповая статистика

Групповая статистика — это `annotate` + `values` + `filter(appointments_count__gt=1)` по врачам.

файл: [apps/appointments/views.py](apps/appointments/views.py)

Первый запрос: активные записи на каждого врача. Второй: только врачи с более чем одной активной записью. `filter` после `annotate` отбирает группы. Отменённые записи в группу не входят.

## 19. select_related()

`select_related("doctor", "doctor__specialty", "patient")` на карточке записи загружает связи одним JOIN.

файл: [apps/appointments/views.py](apps/appointments/views.py)

Страница `/appointments/1/`, вкладка SQL Debug Toolbar: один основной SELECT с JOIN, без отдельных запросов на врача и пациента.

Анализ SQL списка записей делается через Django Debug Toolbar на `/appointments/`.

файлы: [appointment_service/settings.py](appointment_service/settings.py), [appointment_service/urls.py](appointment_service/urls.py)

## 21. Фильтрация, сортировка и пагинация вместе

Фильтрация, сортировка и пагинация работают вместе: `PAGE_SIZE = 5`, ссылки страниц через `{% querystring %}`.

файлы: [apps/appointments/views.py](apps/appointments/views.py), [apps/appointments/templates/appointments/appointment_list.html](apps/appointments/templates/appointments/appointment_list.html)

`/appointments/?doctor=1&sort=date`, затем страница 2: в URL остаются `doctor` и `sort`. Без фильтра 15 записей дают 3 страницы. `Paginator` режет уже отфильтрованный QuerySet.

## 22. Доступность врача на дату

Свободный врач определяется так: заняты только `Appointment.objects.active().for_date(selected_date)`, затем `Doctor.objects.exclude(pk__in=booked_ids)`.

файл: [apps/doctors/views.py](apps/doctors/views.py)

`/doctors/available/?date=2026-09-15`: Смирновой нет, Петров есть, потому что запись 3 отменена. Смена статуса активной записи в админке сразу меняет список свободных.

## 24. TextChoices

Статусы заданы как `Appointment.Status` (`ACTIVE`, `CANCELLED`, `COMPLETED`), а не произвольными строками.

файлы: [apps/appointments/models.py](apps/appointments/models.py), [apps/appointments/templates/appointments/includes/appointment_status.html](apps/appointments/templates/appointments/includes/appointment_status.html)

Сравнения: `status=self.model.Status.ACTIVE` и `appointment.status == appointment.Status.CANCELLED`. В админке смена статуса сразу видна в списке, статистике и свободных врачах.

## 25. Связанные данные без лишних запросов

Связанные имена врача и пациента в списке берутся одним запросом: `select_related` плюс `annotate(...=F(...))`.

файл: [apps/appointments/views.py](apps/appointments/views.py)

`values()` в списке не используется, потому что шаблон работает с объектом записи. `select_related` как раз нужен, чтобы не было N+1. В статистике для узкого набора полей используется `values()`.
