# Сервис записи к врачу

Консольное приложение для онлайн-записи пациентов на прием к врачу.
После ПР3 приложение построено на объектной модели. В ПР5 к нему
добавлен веб-интерфейс на Django: браузер отправляет HTTP-запрос,
маршрутизация вызывает view-функцию, а та возвращает HTML-страницу.
Классы, JSON-хранилище, тесты и консольное меню ПР3 сохранены.

## Назначение

Сервис показывает врачей, специальности, пациентов и записи на прием.
Создание и отмена записей через веб-формы появятся в следующих работах.
Сейчас веб-интерфейс отображает данные и использует проверки ПР3.

## Используемые технологии

- Python 3.10+ (веб-версия проверялась на Python 3.12);
- Django 5.2 — веб-фреймворк;
- HTML — разметка страниц;
- CSS и Bootstrap 5.3 — оформление;
- pytest — автоматизированные тесты;
- flake8 — проверка качества кода.

## Предметная область

Основные сущности:

- врач (`Doctor`);
- специальность (справочник `KNOWN_SPECIALTIES`);
- пациент (`Patient`);
- запись на прием (`Appointment`).

Запись хранит объекты `Doctor` и `Patient`, а не только их поля.
Специальность врача доступна как `appointment.doctor.specialty`.
Отменённая запись остаётся в списке и не блокирует время приема.

## Страницы веб-интерфейса

- `/` — главная страница (`index()`);
- `/doctors/` — список врачей (`doctors()`);
- `/doctors/<int:doctor_id>/` — карточка врача (`doctor_detail()`);
- `/specialties/` — справочник специальностей (`specialties()`);
- `/specialties/<str:specialty_name>/` — врачи специальности
  (`specialty_detail()`);
- `/patients/` — пациенты из записей (`patients()`);
- `/patients/<int:patient_id>/` — карточка пациента
  (`patient_detail()`);
- `/appointments/` — список записей (`appointments()`);
- `/appointments/<int:appointment_id>/` — карточка записи
  (`appointment_detail()`).

Если объект не найден, страница возвращает код 404.
Для неизвестного адреса подключён `handler404`
(`page_not_found()`). Он срабатывает при `DEBUG = False`.

Общий каркас страниц собирает `page()` в `apps/homepage/views.py`:
кодировка, заголовок, Bootstrap 5.3, собственные CSS-правила и
навигация. Остальные приложения импортируют эту функцию.

## Основные операции

### Используется в веб-интерфейсе (ПР5)

- просмотр врачей, специальностей, пациентов и записей;
- карточка врача со слотом, который проверяет `is_slot_available()`;
- отбор врачей специальности через `filter_doctors_by_specialty()`;
- карточка записи со связанными объектами врача и пациента;
- признак несовершеннолетнего пациента через `Patient.is_minor()`.

### Отложено до следующих работ

Эти операции работают в консольной версии. В веб-интерфейсе они
появятся вместе с формами и POST-запросами:

- добавление врача;
- поиск врача по имени;
- сортировка и проверка специальности из формы;
- создание записи;
- отмена записи;
- статистика как отдельное действие пользователя.

## Хранение данных

Данные по-прежнему лежат в JSON:

- `data/doctors.json` — 15 врачей;
- `data/appointments.json` — 15 записей, из них 3 отменены
  (идентификаторы 3, 7 и 12).

Отдельного файла пациентов нет: имя и возраст пациента хранятся
внутри записи. При загрузке `storage.py` создаёт объекты `Doctor`,
`Patient` и `Appointment` и связывает запись с врачом по `doctor_id`.

Django-приложения лежат в пакете `apps/`. Так они не пересекаются с
модулями ПР3 `doctors.py` и `appointments.py` в корне репозитория.

Пациент получил собственное приложение: это сущность проекта, а не
встроенная модель пользователя Django. Специальность тоже вынесена
в приложение, потому что в проекте это отдельная сущность.

## Назначение модулей

### `main.py`

Консольная версия (ПР3): меню и пользовательские сценарии.

### `appointment_service/`

Настройки Django: `settings.py`, корневой `urls.py`, точки входа
`wsgi.py` и `asgi.py`.

### `apps/homepage/`

Главная страница, функция `page()` и обработчик `page_not_found()`.

### `apps/doctors/`, `apps/specialties/`, `apps/patients/`, `apps/appointments/`

View-функции и маршруты соответствующих разделов. Файлы `models.py`
пока пустые: перенос сущностей в Django ORM выполняется позже.

### `entities/`, `doctors.py`, `appointments.py`, `storage.py`

Классы и функции ПР3. Веб-слой их вызывает, а не копирует логику.

## Запуск

Веб-версия:

```text
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

После запуска открыть http://127.0.0.1:8000/.

Консольная версия:

```text
python main.py
```

## Тестирование и качество кода

```text
pytest -v

```

Реализовано в ПР5:

- Django-проект `appointment_service`;

- формы создания и отмены записи;
- API, контейнеризация и CI/CD.
